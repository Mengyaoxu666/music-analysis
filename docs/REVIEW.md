# 原代码快速审查与修复记录

审查对象：此前的 `full_song_spectrum.m`、说明文件和合成/真实歌曲验证脚本。
新代码不是把旧脚本包上窗口，而是拆分了计算、界面、导出与可复现测试。

| 级别 | 原问题 | 本版处理 |
|---|---|---|
| 高 | `compute_welch` 按窗和做幅度标定，而整曲 FFT 窗长不同；两条谱线直接比峰高会产生窗带宽偏差 | 使用 `abs(FFT)^2 / (fs*sum(window^2))`，输出单边PSD；显示ENBW定义，禁止“频率相近即验证通过”的结论 |
| 高 | 语谱图和RMS先把声道取算术平均，反相左右声道可抵消成静音 | 所有谱图逐声道先计算功率再平均；RMS/峰值统计原始声道，不先混音 |
| 高 | 对全曲一次解码并分配全长Hann窗之后才检查FFT内存，检查晚于大内存分配 | 默认Welch/STFT定长读取；可选整曲FFT在整文件读入前检查保守1.5 GiB估算 |
| 中 | `max(256,min(window,n_samples))` 使64～255样本文件窗长越界 | 窗长始终不大于实际样本数，少于4样本给出明确错误 |
| 中 | 对数频带取最大值让频带更宽处噪声底偏高，还把频带中心误作实际峰频 | 显示只做线性功率平均；原始Welch CSV不降采样，FFT显示CSV明确标注为频带均值 |
| 中 | 每首语谱图按自身最大值归一化，导致不同音乐色阶不可比，静音也容易被拉亮 | 固定绝对PSD色标；归一化仅作用于频谱且明确共同频段 |
| 中 | 测试硬编码某首歌的100～140Hz峰、只检查有限性，没有数值基准 | 全合成测试对照SciPy独立Welch、Parseval功率、增益差、反相多声道、不同采样率、301秒尾部能量 |
| 中 | 硬编码本机路径、真实音乐名；旧验证脚本要求整个MATLAB会话无任何图窗 | 新仓库不含私人源数据/路径；离屏Qt测试仅管理自身窗口；支持取消、坏文件隔离 |

## 重要口径修正

- 补零只减小频率网格间隔，不提高窗的真实频率分辨能力。
- PSD积分为均方幅度；以样本满幅1为参考时，满幅正弦的RMS为−3.01 dBFS。
- Welch和整曲FFT即使用同一PSD单位，仍有不同的窗带宽/统计方差，逐峰匹配不是正确性证明。
- 本版归一化是共有频段均方功率归一化，不是LUFS响度匹配或音质评分。
- 首尾完整覆盖指每个样本进入至少一个分析窗口；加窗权重并不恒定，不能据此声称样本等权。

原始私人目录与历史输出保留在原位置，不被自动复制、删除或上传。
